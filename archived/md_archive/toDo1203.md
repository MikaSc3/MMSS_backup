### B – `ffa_evaluator.py`: Statistik-Kern

#### B1 – `CriterionRecord` um `run_id` erweitern
```python
@dataclass
class CriterionRecord:
    ...
    run_id: str = ""   # neu: identifiziert den Run (z.B. "run1", "run3")
```
→ Wird beim Laden durch `load_criterion_records()` befüllt.
→ Rückwärtskompatibel (Default `""`).

#### B2 – Neue Hauptfunktion `statistical_testing_groups()`
Ersetzt die bisherige `statistical_testing()` für den Run-Gruppen-Ansatz.

**Signatur:**
```python
def statistical_testing_groups(
    group_a_runs: Dict[str, List[CriterionRecord]],  # {run_id: records}
    group_b_runs: Dict[str, List[CriterionRecord]],
    name_a: str,
    name_b: str,
    dataset_label: str,
    alpha: float = 0.05,
) -> Dict
```

**Teststrategie:**

Für jede Metrik (Total FFA MAE, Macro F1):

1. Berechne pro Run einen skalaren Wert:
   - MAE: mean(|gt_total_ffa - pred_total_ffa|) über alle gemeinsamen Assemblies
   - Macro F1: mean(macro_f1_per_category_per_assembly) über alle gemeinsamen Assemblies×Kategorien
2. Ergibt: `vec_a = [val_run1, val_run2, ..., val_runN]`, `vec_b` analog
3. **Primärtest: Wilcoxon Signed-Rank** (gepaart wenn gleiche Assemblies, sonst ungepaart)
4. **Sekundärtest: Permutation Test** (`scipy.stats.permutation_test`, n_resamples=10000)
5. Effektgröße: **Rank-Biserial Correlation** $r_{rb} = 1 - \frac{2W}{n(n+1)}$
6. Interpretation: `|r_rb| < 0.3` → klein, `0.3–0.5` → mittel, `> 0.5` → groß

#### B3 – Multiple Testing: Benjamini-Hochberg-Korrektur
**In `run_evaluation.py`** nach Sammlung aller paarweisen Roh-p-Werte:
- Alle Wilcoxon-p-Werte aus allen Vergleichspaaren × Metriken gesammelt
- BH-Prozedur angewendet → adjustierte p-Werte
- `p_adjusted` zusätzlich zum Raw-p-Wert im Output

**Implementierung:** über `statsmodels.stats.multitest.multipletests` mit `method='fdr_bh'`
(oder manuell implementieren falls statsmodels nicht verfügbar)

#### B4 – Broken t-Test entfernen / ersetzen
Der aktuelle Code `ttest_rel(diffs, zeros)` wird entfernt.
Ersatz: Permutation Test (B2 oben) ist der zweite Test.
Begründung: t-Test bei kleinen n nur sinnvoll wenn Normalverteilung plausibel → bei n=7 Runs nicht prüfbar.

#### B5 – `mean_std_summary()` Hilfsfunktion
```python
def mean_std_summary(values: List[float]) -> Dict:
    return {
        "mean": round(np.mean(values), 4),
        "std":  round(np.std(values, ddof=1), 4),
        "min":  round(np.min(values), 4),
        "max":  round(np.max(values), 4),
        "n":    len(values),
    }
```

#### B6 – `interpret_effect_size()` Hilfsfunktion
```python
def interpret_effect_size(r_rb: float) -> str:
    r = abs(r_rb)
    if r < 0.3:   return "klein"
    if r < 0.5:   return "mittel"
    return "groß"
```

## Empfohlene Ordnerstruktur (Experiments-Folder)

### Konzept: Ein `_*`-Ordner = eine Evaluierungsgruppe

Ein `_*`-Ordner enthält **alle Bedingungen + alle Runs** die du miteinander vergleichen willst.
Die Evaluation öffnet diesen Ordner, gruppiert nach Bedingung (strip `_run{N}`) und testet alles quer durch.

### Zielstruktur

```
data/experiments/
  _Vergleich_ffa_only_2026-03-12/          ← eine Evaluierungsgruppe (Prefix "_")
      JadeDate_exp_baseline_ffa_only_run1/ ← Bedingung A, Run 1
      JadeDate_exp_baseline_ffa_only_run2/ ← Bedingung A, Run 2
      ...
      JadeDate_exp_baseline_ffa_only_run10/
      CoralApple_exp_baseline_ffa_only_run1/ ← Bedingung B, Run 1
      ...
      CoralApple_exp_baseline_ffa_only_run10/
      evaluation/                          ← auto-generiert
          group_summary.json               ← mean ± std pro Bedingung
          statistical_testing.json         ← alle paarweisen Tests
          plots/
```

**Benennungsregel:**
- Bedingungsname = alles VOR dem letzten `_run{N}` (z.B. `JadeDate_exp_baseline_ffa_only`)
- Run-Nummer = der `_run{N}`-Suffix

**Gruppenbildung durch Evaluation:**
```python
"JadeDate_exp_baseline_ffa_only_run1"  →  Gruppe: "JadeDate_exp_baseline_ffa_only"
"JadeDate_exp_baseline_ffa_only_run2"  →  Gruppe: "JadeDate_exp_baseline_ffa_only"
"CoralApple_exp_baseline_ffa_only_run1" → Gruppe: "CoralApple_exp_baseline_ffa_only"
```

### Wie du die Runner auf dieses Ziel ausrichten kannst

Aktuell schreibt jeder Runner in ein neues `run_{TIMESTAMP}_*`-Verzeichnis.
Um mehrere Bedingungen in **einen** `_*`-Ordner zu schreiben, gibt es zwei Wege:

**Option 1 (empfohlen – kein Code-Umbau): Runner separat aufrufen, dann manuell/scripten zusammenkopieren**
- Jeder Config-Satz (z.B. `exp_gpt4o_ffa_only.yaml`, `exp_gpt41_ffa_only.yaml`) erzeugt seinen eigenen
  `run_{TIMESTAMP}`-Ordner
- Ein kleines Sammel-Script `collect_for_evaluation.py` verschiebt/linkt die
  Experiment-Unterordner in einen gemeinsamen `_*`-Ordner

**Option 2 (sauberste Lösung): `--output-dir`-Parameter in Runner ergänzen**
```bash
python run_experiments_ffa_only.py --output-dir data/experiments/_Vergleich_ffa_only_2026-03-12
python run_experiments_sequence_gt.py --output-dir data/experiments/_Vergleich_ffa_only_2026-03-12
```
→ Beide Runner schreiben direkt in denselben `_*`-Ordner.
→ Erfordert kleine Ergänzung in `run_all_experiments()` beider Runner (~5 Zeilen).

**Für jetzt empfohlen: Option 2**, weil es sauber, reproduzierbar und skriptfähig ist.
